# Помощник по регламентам и документам (v2)

## Что было не так в v1
Бот искал вопрос пользователя среди вопросов из `golden_set.json` и возвращал готовый `reference_answer`. Это тестовый набор, а не база знаний:
новые формулировки не работали, шаблонов, диалога, проверки документов и отказов «нет в базе» не было, источники были вшиты в текст.

## Как устроено теперь
```
Вопрос → Диалог (сессия, намерение) ─┬─ уточнение (не хватает данных)
                                      ├─ поиск по базе знаний (BM25 + порог релевантности)
                                      │      └─ ниже порога → честный отказ + куда обратиться
                                      ├─ ответ: локальная LLM (Ollama) строго по найденным положениям,
                                      │         без LLM — цитаты положений; ссылки [id] проверяются кодом
                                      ├─ шаблон: подбор модуля → извлечение данных из текста → вопросы по пропускам → черновик
                                      └─ проверка документа: правила (пропуски, лишние элементы шаблона, единообразие, даты) + маршрут визирования и порядок действий
```
- `knowledge_base/` — документы. `.md` с заголовками `## [id] название | ссылка`, либо `.docx/.pdf/.txt` (режутся по нумерованным пунктам). В шапке `.md`: `doc`, `version`, `status: active|archived`, `access: public|restricted`.
- `templates/*.json` — модули: поля, вопросы, текст, связанные положения Матрицы. Новый модуль = новый JSON.
- `golden_set.json` — только для оценки: `python -m eval.run_eval` (результат сейчас 13/14, см. ниже).

## Запуск
```
pip install -r requirements.txt
uvicorn main:app --port 8000          # UI: http://localhost:8000, API-доки: /docs
# по желанию LLM (open source, локально):  ollama pull qwen2.5:7b-instruct
```
Без Ollama бот работает в режиме цитат. Переменные: `OLLAMA_URL`, `OLLAMA_MODEL`, `LLM_ENABLED=0/1`, `ANSWER_THRESHOLD`, `WEAK_THRESHOLD`.

## ВАЖНО: база знаний
В `knowledge_base/seed_from_golden_set.md` лежит временный корпус, собранный только из фактов в эталонных ответах golden set (id положений совпадают с `expected_chunk_ids`).
Положите туда реальные Инструкцию, Матрицу визирования, модули и Методрекомендации и вызовите `POST /api/kb/reload` (заголовок `X-Role: doc_expert`).
После этого сверьте шаблон `is_commissioning.json` с официальным модулем (это каркас) и прогоните eval заново.

## Защита информации и риски (для защиты проекта)
- Локальная LLM, данные не уходят наружу. Журнал `logs/audit.jsonl` хранит только метаданные (без текста вопросов и документов).
- Ролевая модель: у положений есть `access`, роль приходит заголовком `X-Role` (в проде из SSO портала).
- Снижение ошибок: ответ только по найденным положениям; порог релевантности; ответ LLM без валидных ссылок отбрасывается; «не знаю» вместо выдумки; темы, которые Инструкция не регламентирует (сопроводительное письмо), прямо помечены.
- Версионность: `version` + `status`; архивные версии не участвуют в поиске; в источниках показывается версия.
- Расширение: новые документы — файлы в `knowledge_base/`, новые процессы — модули в `templates/`, замена BM25 на эмбеддинги (bge-m3) — в `retrieval.py`.
